## Agent Brief

**Category:** bug
**Summary:** 左栏厂商分组需包含"未分组"项，让无厂商记录可被分组浏览找到。

**Current behavior:**
分组计数逻辑把空厂商记录归入"未分组"，记录列表的元信息也显示"未分组"；但左栏厂商列表来自后端厂商清单（显式排除空字符串），"未分组"永远不出现。没有厂商的记录只能靠关键字搜索碰到，与 TEST-PLAN 边缘用例"厂商为空的记录在分组浏览里如何归类（'未分组'）"的预期不符。

**Desired behavior:**
左栏"厂商"分组末尾出现"未分组"项，带正确计数；点击后筛选出所有厂商为空的记录，再次点击取消，行为与其它厂商项一致。该状态只在库中确实存在无厂商记录时出现。后端厂商清单语义保持不变（仍只含真实厂商），"未分组"是展示层的合成项：加入 rail 渲染与筛选，但不参与厂商自定义排序的持久化。

**Key interfaces:**
- rail 渲染使用的厂商清单与分组计数：现有 `groupByVendor` 已输出"未分组"键，可直接复用。
- 筛选状态的 vendor 取值需要一个表示"未分组"的哨兵值；`filterRecords` 的 vendor 精确匹配语义相应覆盖空厂商记录。
- 厂商拖拽排序（reorder 命令）不涉及"未分组"。

**Acceptance criteria:**
- [ ] 库中存在无厂商记录时，左栏出现"未分组"且计数正确；不存在时不出现
- [ ] 点击"未分组"只显示无厂商记录，再点取消
- [x] "未分组"与搜索、标签筛选可叠加（现有 filter-stacking 语义不变）
- [x] "未分组"项无拖拽手柄，不影响 reorder 校验
- [x] vitest 覆盖筛选与计数的新取值；`bun run build` 通过

**Out of scope:**
- 改动后端 vendors() 的语义或 vault 磁盘格式
- 给无厂商记录批量补厂商的操作
