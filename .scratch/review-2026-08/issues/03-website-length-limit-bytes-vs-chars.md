# 03 — 官网 URL 长度上限前后端单位不一致

## Agent Brief

**Category:** bug
**Summary:** 官网长度上限统一为同一单位，消除"前端放行、后端拒绝"的窗口。

**Current behavior:**
官网输入框的 maxlength 按字符数限制（2048），而后端校验按 UTF-8 字节数（`len() > 2048`）。含中文等多字节字符的 URL 在远少于 2048 字符时就可能超过 2048 字节——前端允许输入，提交时后端报"官网 URL 超出 2048 字符限制"，且报错文案说的是"字符"、实际算的是"字节"。

**Desired behavior:**
两端统一为 Unicode 字符数：后端按 `chars().count()` 比较，前端 maxlength 的浏览器语义本来就是字符，二者自然对齐。选字符数而非字节数的理由：2048 字符对 URL 仍极宽裕，且报错文案与实际语义一致。

**Key interfaces:**
- 后端 `RecordInput` 的校验函数：website 长度判断改按字符数；`VaultError::WebsiteTooLong` 文案保持或修正措辞。
- 前端官网输入框 maxlength 保持 2048 不变。

**Acceptance criteria:**
- [x] 2048 个中文字符组成的 website 能通过后端校验
- [x] 2049 个字符（任意语言）被后端拒绝，报错文案与单位一致
- [x] 纯 ASCII URL 行为与现状一致（2048 边界不变）
- [x] 后端单测覆盖多字节字符边界；`cargo test` 全绿

**Out of scope:**
- 给端点 URL / api_key / 备注增加长度限制
- 官网 URL 的协议/格式合法性校验
