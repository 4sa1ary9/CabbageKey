# 保持 Rust + Tauri + JS 技术栈，不做语言重写

2026-08-03，用户曾要求"推倒重来，用最合适的语言重写"。经质询确认：重写的真实痛点是功能冗余与"不好改"，不是语言。绿场分析（不计沉没成本重新选型）显示，"本地单机加密/存储类桌面 GUI"的最优集合是"编译型后端 + 一流生态 + webview UI"（Go+Wails 与 Rust+Tauri 并列首选），现有栈已在该集合内；换栈只能买到约 5% 的口味差异，却要付出加密层重写、KAT 重 pin、测试作废、旧 vault 兼容的代价。项目由 agent 维护、用户不亲自写码，"换成我会的语言"这一理由不成立。**决定：保持 Rust + Tauri 2 + Vite/原生 JS，通过删改与 UI 层重做解决痛点。**

## Considered Options

- **Go + Wails**：绿场并列首选（单静态二进制、编译快、工具链零配置），但与现有栈是口味级差异，不值得重写。
- **Python + GUI**：仅在产品形态改为 CLI/TUI 时最优；桌面 GUI 打包（PyInstaller）又大又脆。
- **同栈全推倒重写**：可获得"全新"感，但厂商预设数据与测试需无收益重誊。
