# Design: 本地无密码 API Key 收纳工具（KeyVault）

> 本文档于 2026-08-04 随明文化重构（ADR-0002）改写：原稿中"本地加密""主密码""丢网盘同步"的设计前提已全部失效，替换为"明文、无密码、可文件夹迁移"的新现实。术语以 `CONTEXT.md` 为准；决策记录见 `docs/adr/`（ADR-0001 保持 Rust+Tauri 技术栈、ADR-0002 明文化无密码）。

## Problem Statement

用户的 API key / 密钥 / 配套 URL 高度碎片化，散落在环境变量、笔记、文档、邮件、各家后台等多个地方。三样本该绑在一起的信息（厂商、用途、key、url）是分开存的，导致两个具体痛点：
1. 取用麻烦——主要在浏览器/后台界面里复制粘贴 token 和 url，找到 key 还得再跑一趟文档去捞对应 url。
2. 找回麻烦——位置混乱，经常在好多地方找 key；有时攥着一个 key 却不知道它对应什么使用场景（缺用途名称），不知道用在哪里。

现有方案（KeePassXC、pass、1Password、Bitwarden、Doppler/Infisical/Vault）要么是"账号+密码"的形状、把 url 和"用途"当二等公民，要么是面向团队/云端的重型工具。没有一个专门为"厂商 + 用途 + api_key + url"这一新形状（人手十几个大模型/API 厂商的 key）做收纳与找回。这个缺口就是本项目的机会。

## What Makes This Cool

让"用途 + api_key（+ 厂商 + url + 备注 + 标签）"作为一个不可分割的整体存在一个地方：存的时候逼你把用途和 key 配齐，取的时候一次拿全、一键复制，永远不用再去别处对照。把通用密码管理器的盲区（url 和用途不是一等公民）变成本工具的核心卖点。

在此之上，用三条腿解决"位置混乱、不知道用在哪"：

- **厂商作为分组维度（不只是文本字段）。** 录入时从已有厂商里选择，没有则新建，不用手打。这消灭"DeepSeek / deepseek / 深度求索"这类拼写不一致把同一厂商拆成几堆的问题；列表可按厂商折叠分组浏览。
- **标签作为跨厂商的横切分类。** 厂商回答"谁家的"，标签回答"干嘛用的 / 哪个项目 / 是否已废弃"。同一标签（如 `翻译`、`项目A`、`已废弃`）可贴在不同厂商的 key 上，按标签筛选。与必填的"用途名称"不冲突——用途名称是该记录的名字，标签是可跨记录复用的筛选维度。
- **关键字搜索。** 即时过滤用途名称 / 备注 / 厂商。

三者并存：厂商分组浏览、标签筛选、关键字搜，覆盖"我记得是某厂的""我要找某用途的""我只记得名字一部分"三种找回路径。

## Constraints

- 完全本地单机；无密码、无加密、无账号（ADR-0002）。
- 数据以明文 JSON 存于单个 vault 文件，人类可读；迁移 = 拷贝文件或整个文件夹到另一台机器直接使用。
- 不做网盘同步、不做多设备、不做云端服务（"同步" ≠ "迁移"，见 CONTEXT.md）。
- 单人自用工具，先不做团队/共享/权限。
- "可分享"指代码开源或给朋友自己装来用，不是多人协作同一份库。
- 主力平台 Windows（用户环境 Win 11）；跨平台分发为加分项。

## 威胁模型（用户已知情接受）

- API key 明文落盘：任何能读本机硬盘的程序/人/备份软件都可取得 key 原文。
- 兜底是本机账户密码 / BitLocker 全盘加密，与 `~/.aws/credentials`、`~/.ssh` 明文私钥同级。
- 明文的自然推论：**不要把 vault 文件放进网盘/云同步目录**——一旦上传即泄露。
- 防数据丢失依赖两点：原子写（防崩溃半截文件）+ 用户自己的文件夹备份习惯（`.bak` 自动备份已删除）。

## 架构决策

- **D1 技术栈：Tauri 2（Rust 后端 + 系统 WebView）保持不动。** 理由见 ADR-0001：绿场选型中"编译型后端 + 一流生态 + webview UI"本就是最优集合，换栈只买口味差异、付重写代价。
- **D2 存储：单个明文 JSON vault 文件（schema_version 1）。** 顶层 `schema_version` + `records` 数组；启动整读进内存，改动整写回（原子写 tmp+rename）。**格式自此冻结**，由 golden test 逐字节把守——接替原 KAT"防静默改格式"的角色。
- **D3 记录 schema：** `id`（uuid 主键，重名按 id 区分）+ `order`（列表显示顺序；旧 vault 无此字段时按文件位置兜底补齐，显式值保留）+ 必填 `name`（用途名称）/ `api_key` + 可选 `vendor` / `endpoints`（接口规范 → 端点 URL 映射，BTreeMap 保证序列化键序确定）/ `website` / `note` / `tags`（多值）/ `created_at` / `updated_at`。完整向后兼容旧字段（缺省自动默认）。
- **D4 启动流程：无密码。** 启动读本机配置（仅 `last_path` + `vault_history`，无任何凭据），上次 vault 存在则直进主界面；不存在或首次启动进选择页（打开已有 / 新建 / 历史列表，失效路径置灰、可单条移除）。主界面内"切换 vault"关闭当前会话回选择页。
- **D5 会话状态：只有当前 vault + 路径。** 无密码、无凭据、无哈希校验。`open_vault` 读文件解析 JSON 即载入；`create_vault` 写空 vault。
- **D6 前端：薄 DOM 壳 + 纯逻辑模块。** `main.js` 只做事件绑定与渲染；检索（filter）、厂商预设（vendorPresets）、表单状态机（formState）、历史标注（history）全部为可单测的纯逻辑模块。

## 已删除（从加密时代移除，见 ADR-0002）

- 整个加密层：Argon2id / AES-256-GCM / KAT 固定向量测试、crypto 模块。
- 锁屏三模式（choose / unlock / create）、主密码、记住我/免密登录、config.json 凭据。
- 网盘同步设计：sha256 冲突检测、保存前哈希比对警告、`.bak` 自动备份。
- 明文导出命令（vault 本身就是明文）。
- 一次性迁移工具 `migrate_vault`（已完成使命，与 crypto 同批删除）。
- 依赖清理：aes-gcm / argon2 / rand / zeroize / sha2 / base64 / hex 全部移除。

## 保留（与旧设计一致的部分）

- 厂商分组、标签横切筛选、关键字搜索三路叠加。
- 三栏 UI 与设计代头（见下"UI 设计"段）。
- 字段级一键复制 + 剪贴板自动清空（30 秒）。
- 原子写（tmp+rename）。
- 厂商预设 + 4 种接口规范 + endpoints 映射、官网超链接。
- vault 历史列表（最多 10 条、最新在前、按路径去重）。

## UI 设计

分类：**App UI**（工作区型、数据密集、任务导向），适用 App UI 规则——平静的表面层级、强排版、少颜色、少装饰，卡片只在"卡片本身就是交互"时才用。

### U1 主界面：三栏布局（筛选 / 列表 / 详情）

```
┌─────────────────────────────────────────────────────────────┐
│  🔍 搜索用途/厂商/备注...                      [+ 新增]  [切换] │  顶部:搜索常驻+主操作
├──────────────┬──────────────────────────────────────────────┤
│ 全部 (42)     │   DeepSeek · 翻译用                            │  详情面板:选中项全字段
│ ─────────    │   ┌────────────────────────────────────────┐ │
│ ▾ 厂商        │   │ api_key  sk-xxxx...xxxx        [复制] 👁 │ │  key 默认遮罩,点睛显示
│   DeepSeek(3)│   │ url      https://api.deep...   [复制]    │ │  url 独立复制键
│   OpenAI (5) │   │ 厂商      DeepSeek                        │ │
│   Claude (2) │   │ 标签      #翻译  #项目A                   │ │
│ ─────────    │   │ 备注      个人账号, 6月续费              │ │
│ ▾ 标签        │   └────────────────────────────────────────┘ │
│   #翻译 #项目A│         [编辑]   [删除]                        │
│   #已废弃     │                                                │
├──────────────┤   左栏:厂商分组+标签都是"筛选器",点一下过滤    │
│ 中间列表:     │   右侧列表; 不是导航,是缩小范围。三条检索       │
│ ▸ 翻译用      │   路径(搜索/分组/标签)叠加,不互相打架。        │
│ ▸ 对话测试    │                                                │
└──────────────┴──────────────────────────────────────────────┘
```

信息层级：搜索框 + 左栏筛选器是第一眼（治"位置混乱"），中间列表第二，详情面板第三。厂商分组和标签都是**常驻筛选器**而非两个竞争的视图——搜索按文本缩小、左栏点击按厂商/标签缩小，三者叠加。

### U2 vault 选择页（无密码）

- 首次启动或切换 vault 时出现：**打开已有 vault** / **新建 vault** 两个入口。
- 下方为最近使用历史（最多 10 条）：点击即打开；文件不存在的条目置灰并标"文件不存在"；× 按钮单条移除。
- 上次使用的 vault 文件缺失时，页面顶部提示"上次使用的 vault 文件不存在，请重新打开或新建"。

### U3 空状态（两种区分对待）

- **首次空库**：一句欢迎语 + 大的"新增第一个密钥"主按钮 + 一行提示该填什么（用途、key）。引导开始，不是冷冰冰"暂无记录"。
- **搜索/筛选无结果**："没有匹配的记录" + 一个"清除筛选"按钮给出口。

### U4 复制反馈 + 剪贴板清空

点复制后：按钮瞬间变"✓ 已复制"维持约 1.5s，底部出一条提示"api_key 已复制，× 秒后自动清空剪贴板"。明确告知复制成功 + 何时会清，用户不用猜。清空倒计时可见（30 秒）。

### U5 最小设计代头

- **字体**：一款真正文字体（非 system-ui/Inter/Arial 默认栈）+ 一款**等宽字体专门渲染 api_key / url**（等宽让密钥字符串更好认、更难看错）。
- **主色**：一个强调色（非紫蓝渐变默认），其余走中性灰阶。
- **间距刻度**：4 / 8 / 16 / 24 一套，统一留白。

## 表单（录入/编辑）

字段顺序：厂商 → 用途名称* → api_key* → 接口规范（多选 toggle）+ 端点 URL → 官网 → 标签 → 备注。

- 厂商为下拉选择（内置 10 家预设 + 自定义），选中自动填充官网、接口规范、端点 URL。
- 4 种接口规范：OpenAI Chat Completions / OpenAI Responses API / Anthropic Messages / Gemini generateContent；多协议厂商可自由切换，URL 联动；单协议厂商选不支持的规范时提示并回退。
- 端点 URL 按规范分别保存（endpoints 映射），详情面板可切换查看各规范 URL。
- 必填校验：用途名称 / api_key 缺失时阻止提交并提示；website 上限 2048 字符。
- 所有输入 `autocomplete="off"` 禁用浏览器自动填充。

## NOT in scope（明确不做）

- **任何形式的加密 / 密码 / PIN / OS keychain / DPAPI / "伪加密"** — ADR-0002 否决，仓库不含加密代码。
- **自建后端 / 云端服务 / 网盘同步 / 多设备冲突合并** — 迁移才是答案，同步不是。
- **团队/共享/多人协作同一库** — 单人工具。
- **同时打开多个 vault** — 会话只支持一个当前 vault，切换即替换。
- **移动端 / CLI / Web 版 / 浏览器扩展**。
- **CI 跨平台打包发布流水线** — 记入 `TODOS.md`，本地跑通后再做。
- **支持上千/上万条记录的性能优化** — 数据量 <100，JSON blob 足够。
- **完整无障碍审计** — 记入 `TODOS.md`；v1 保证键盘可用 + 触控目标/对比度基本达标。
- **深色模式 / 真实品牌图标** — 记入 `TODOS.md`。

## Failure modes（每条新代码路径的生产故障）

| 路径 | 故障方式 | 有测试? | 有错误处理? | 用户可见? |
|------|---------|--------|-----------|----------|
| 打开 | vault 文件损坏/不是合法 JSON | — | ✓ 干净报错 | ✓ 选择页报错 |
| 打开 | 文件被外部删/移（启动时 last_path 失效） | — | ✓ 提示+选择页 | ✓ 明确提示 |
| 保存 | 写到一半崩溃 | ✓ 原子写 | ✓ 临时文件+rename | 数据不损坏 |
| 启动 | 无 last_path / 首次运行 | ✓ 前端 | ✓ 选择页 | ✓ 选择页 |
| 编辑 | 编辑期间文件被外部程序改 | — | 无（设计取舍：本地单机无并发） | 以最后写入为准 |

无静默失败的关键路径——JSON 解析失败、必填校验、路径缺失都有显式报错。

## 测试策略

好测试的标准：只测模块边界上的外部行为（输入→输出、可观察的副作用），不测内部实现细节。

- **后端（cargo test，26 个）**：vault 模块 CRUD / 必填校验 / api_standard 验证 / website 长度 / 重名按 id 区分 / 分组标签去重 / JSON round-trip / **明文格式 golden test**（字面量 JSON ↔ 序列化双向逐字节一致，冻结磁盘格式）/ 记录顺序（旧 vault 兜底、重排校验、新增排最后、编辑不动顺序）/ 历史列表（去重、上限、display_name）。
- **前端（vitest，56 个）**：filter（10）/ vendorPresets（17）/ formState（25）/ history（4）——全部纯函数、直接断言返回值。
- **Tauri 命令层**：不加测试接缝，保持薄壳，逻辑全部下沉到 vault 模块。
- **不引入 DOM/E2E 自动化测试**：维持项目"纯逻辑单测 + 人工走查"的传统；发布前按 `docs/TEST-PLAN.md` 的人工清单走一遍（直进主界面 → 增 → 搜 → 复制 → 改 → 删 → 文件夹迁移）。
